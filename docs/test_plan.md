# ORM 运行时功能测试计划

## 1. 测试目标

验证 `include/ess/orm/core` 目录下的运行时功能正确性、稳定性和性能，包括：

- 查询功能（带表类型和不带表类型）
- 事务管理（lambda 风格事务）
- 结果集映射
- 连接池管理
- 缓存机制

## 2. 测试范围

### 2.1 核心运行时功能

| 功能模块 | 文件                    | 主要功能                                                | 测试重点                         |
| -------- | ----------------------- | ------------------------------------------------------- | -------------------------------- |
| 查询系统 | `runtime.hpp`           | 4种查询变体（带表/不带表 × FixedString/SqlParseResult） | 编译期校验、运行时映射、参数绑定 |
| 事务管理 | `transaction.hpp`       | lambda 风格事务、嵌套事务、读写事务                     | 事务隔离、嵌套规则、异常回滚     |
| 结果映射 | `result_set_mapper.hpp` | 表类型映射、Row 对象映射                                | 字段匹配、类型转换、性能优化     |

| 缓存系统 | `cache.hpp`             | 查询结果缓存                                            | 缓存命中、失效策略、内存管理     |

> 缓存可以仅测试自身部分，不用结合query来测试，因为后续我会将其结合clang libtooling做成aop的形式使用，因此目前只考虑缓存自身是否存在问题即可

### 2.2 潜在问题识别

基于代码分析发现以下潜在风险点：

1. **查询限制问题** (`runtime.hpp:44-65`)
   - 带表类型查询对 JOIN、列别名、表达式列的限制
   - 编译期难以验证 JOIN 查询是否只包含主表列
   - 选项：A) 完全禁止 JOIN B) 运行时检查 C) 编译期分析
     > 这是我刻意限制的，因为受限于时间，对列的存在性做校验比较复杂（列部分用子查询时检验复杂，且难以同时映射到多个表上，只能让用户实现dto来进行
     > 映射），耗费时间且性价比不高，因此当前版本直接禁止了join查询

2. **事务嵌套问题** (`runtime.hpp:124-129`)
   - 写事务不能嵌套在读事务中
   - 异常处理机制（catch int 的特殊处理）
     > catch int 这块我目前还没想好，因此可以先放下，只考虑事务嵌套回滚之类的问题即可

3. **线程安全问题** (`runtime.hpp:86-102`)
   - `thread_local` 变量用于事务状态管理
   - 连接池的并发访问安全

4. **类型映射问题** (`result_set_mapper.hpp`)
   - 枚举类型处理 (`std::is_enum_v<T>`)
   - 字符串和数值类型的转换

## 7. 风险评估和缓解

### 7.1 技术风险

1. **编译期校验复杂性**
   - 风险：复杂的模板元编程可能导致编译错误难以调试
   - 缓解：分阶段实现，先实现运行时检查，再逐步迁移到编译期

2. **线程安全问题**
   - 风险：`thread_local` 使用不当可能导致数据竞争
   - 缓解：加强并发测试，使用线程检查工具

3. **内存泄漏**
   - 风险：连接池、缓存可能导致内存泄漏
   - 缓解：使用 Valgrind 进行内存检查

### 7.2 进度风险

- 风险：测试用例数量多，执行时间长
- 缓解：优先级排序，先核心功能后边缘功能

## 9. 附录

### 9.1 测试数据表结构

```sql
-- goods 表
CREATE TABLE goods (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    title TEXT NOT NULL DEFAULT 'untitled',
    price REAL DEFAULT 0.0,
    stock INTEGER DEFAULT 0,
    status INTEGER DEFAULT 2,
    enabled BOOLEAN DEFAULT TRUE
);

-- users 表
CREATE TABLE users (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    name TEXT NOT NULL,
    email TEXT UNIQUE,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

-- orders 表
CREATE TABLE orders (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    user_id INTEGER,
    goods_id INTEGER,
    quantity INTEGER,
    total_price REAL,
    status INTEGER DEFAULT 0,
    FOREIGN KEY(user_id) REFERENCES users(id),
    FOREIGN KEY(goods_id) REFERENCES goods(id)
);
```
