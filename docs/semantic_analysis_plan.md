# SQL 语义分析实施计划

## 概述

在完成语法分析（SELECT/INSERT/UPDATE/DELETE）的基础上，现在开始实施编译期语义分析。语义分析将验证SQL语句的逻辑正确性，包括列存在性、类型兼容性、函数调用正确性等。

## 当前状态

### 已完成
- ✅ 完整的SQL语法分析器（SELECT/INSERT/UPDATE/DELETE）
- ✅ 编译期词法分析和语法分析
- ✅ 基础错误检测（语法错误、结构错误）
- ✅ `operator""_sql` 编译期验证

### 待实现
- ⭕ 基础语义分析（对所有SQL）
- ⭕ 模式语义分析（对带表类型的SQL）
- ⭕ 占位符语义分析

    │   ├── 语句完整性验证
    │   ├── 基本类型兼容性
    │   └── 函数调用基本验证

        ├── 列存在性验证

### 阶段2：占位符语义分析 (预计: 3天)

#### 目标
实现占位符(`?`)的语义验证，这是最有价值的功能。

#### 具体任务
1. **占位符计数验证** - 验证占位符数量与参数数量匹配
   ```cpp
   // 错误示例：占位符数量不匹配
   query<Goods, "SELECT * FROM goods WHERE id = ? AND name = ?"_sql>(123);
   // 期望2个参数，实际1个参数
   ```

2. **占位符上下文分析** - 记录每个占位符的上下文信息
   - 在WHERE条件中
   - 在SET子句中  
   - 在VALUES子句中
   - 在表达式中的位置

3. **基础类型推断** - 根据上下文推断占位符期望类型
   ```cpp
   // 示例：WHERE id = ?
   // 推断：期望整数类型（如果id是整数列）
   ```

4. **参数数量编译期验证** - 在`query_impl`中验证参数数量

#### 验证标准
- 占位符数量错误在编译期被捕获
- 可以正确统计SQL中的占位符数量
- 占位符上下文信息被正确记录

---

### 阶段3：列存在性验证 (预计: 3天)

#### 目标
验证带表类型查询中的列名是否存在。

#### 具体任务
1. **模式信息提取器** - 从ORM模型提取列信息
   ```cpp
   template<typename Model>
   struct SchemaExtractor {
       static constexpr auto get_columns() {
           // 从Model::Schema提取列名和类型
       }
   };
   ```

2. **列引用收集** - 在解析时记录所有列引用
   - SELECT列表中的列
   - WHERE条件中的列
   - SET子句中的列
   - ORDER BY/GROUP BY中的列

3. **列存在性验证器** - 验证列名是否存在于模型中
   ```cpp
   // 错误示例：列不存在
   query<Goods, "SELECT non_existent FROM goods"_sql>();
   ```

4. **表名验证** - 验证FROM子句中的表名与模型匹配
   ```cpp
   // 错误示例：表名不匹配
   query<Goods, "SELECT * FROM users"_sql>();
   ```

#### 验证标准
- 列不存在错误在编译期被捕获
- 表名不匹配错误在编译期被捕获
- 支持带表前缀的列名（`goods.id`）

---

### 阶段4：基本类型兼容性 (预计: 4天)

#### 目标
验证SQL表达式中的类型兼容性。

#### 具体任务
1. **表达式类型推断** - 推断每个表达式的类型
   - 列引用：使用列的类型
   - 字面量：根据字面值推断类型
   - 函数调用：根据函数签名推断返回类型
   - 算术表达式：根据操作数和运算符推断类型

2. **类型兼容性规则** - 定义类型转换规则
   ```cpp
   // 规则示例
   INTEGER + INTEGER → INTEGER
   INTEGER + REAL → REAL
   TEXT + TEXT → TEXT
   TEXT + INTEGER → 不兼容
   ```

3. **算术表达式验证** - 验证`+`, `-`, `*`, `/`, `%`的类型兼容性

4. **比较表达式验证** - 验证`=`, `!=`, `<`, `>`, `<=`, `>=`的类型兼容性

5. **逻辑表达式验证** - 验证`AND`, `OR`, `NOT`的操作数类型

#### 验证标准
- 类型不兼容错误在编译期被捕获
- 支持常见的类型转换规则
- 表达式类型推断正确

---

### 阶段5：函数调用语义 (预计: 3天)

#### 目标
验证函数调用的正确性。

#### 具体任务
1. **函数签名库** - 定义内置函数的签名
   ```cpp
   struct FunctionSignature {
       std::string_view name;
       std::array<SqlType, N> param_types;
       SqlType return_type;
   };
   ```

2. **函数参数验证** - 验证参数数量和类型
   ```cpp
   // 错误示例：参数类型不匹配
   query<Goods, "SELECT UPPER(price) FROM goods"_sql>();
   // UPPER期望TEXT参数，但price是REAL类型
   ```

3. **聚合函数语义** - 验证聚合函数的特殊规则
   - COUNT可以接受任何类型
   - SUM/AVG需要数值类型
   - GROUP BY上下文验证

4. **函数重载处理** - 处理同名函数的不同签名
   ```cpp
   // ABS有两个重载：ABS(INTEGER)和ABS(REAL)
   ```

#### 验证标准
- 函数不存在错误在编译期被捕获
- 函数参数错误在编译期被捕获
- 聚合函数使用正确性验证

### 阶段6：高级语义特性 (预计: 5天)

#### 目标
实现更复杂的语义验证。

#### 具体任务
1. **子查询语义** - 验证子查询的类型和形状
   ```cpp
   // 错误示例：子查询返回多列
   query<Goods, "SELECT * FROM goods WHERE id = (SELECT id, name FROM goods)"_sql>();
   ```

2. **JOIN语义** - 验证JOIN条件的正确性
   - ON条件中的列存在性
   - JOIN表的列引用

3. **CTE语义** - 验证WITH子句的正确性
   - CTE列名定义
   - CTE递归检查（基础）

4. **复合查询语义** - 验证UNION/INTERSECT/EXCEPT
   - 列数量匹配
   - 列类型兼容性

5. **占位符类型精确推断** - 基于列类型推断占位符类型
   ```cpp
   // 精确类型推断
   query<Goods, "SELECT * FROM goods WHERE id = ?"_sql>(123);     // ✅
   query<Goods, "SELECT * FROM goods WHERE id = ?"_sql>("text");  // ❌
   ```

#### 验证标准
- 子查询语义错误在编译期被捕获
- JOIN语义错误在编译期被捕获
- 占位符类型精确推断工作正常

## 实施原则

### 1. 渐进式实施
- 每个阶段独立可验证
- 保持向后兼容性
- 先实现核心功能，再完善细节

### 2. 编译期优先
- 所有语义分析在编译期完成
- 不增加运行时开销
- 利用C++20/23的编译期特性

### 3. 错误友好性
- 提供详细的错误信息
- 指出错误位置和原因
- 提供修复建议

### 4. 测试驱动
- 每个功能添加测试用例
- 验证正确行为和错误行为
- 确保回归测试

## 风险与应对

### 风险1：编译期性能下降

### 风险3：错误信息不友好

### 风险4：向后兼容性问题
