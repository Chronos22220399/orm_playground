# Gap Checklist — 论文与实际实现的差异记录

> 本文档用于记录论文/任务书中提及但当前代码未完整实现或实现方式存在偏差的功能项。
> 后续修改论文和开题报告时可参考此清单调整措辞。

---

## 1. 缓存模块

### 论文/任务书中的描述
- 「无感知缓存模块设计，默认提供LRU、FIFO等常用缓存置换策略」
- 「AI预测性缓存」
- 「开发者无需额外编写缓存控制代码」

### 实际实现
- `include/ess/orm/core/cache.hpp` 提供 `BasicCache`（LRU/LFU/FIFO/Random）和 `QueryResultCache`
- 缓存组件**与 runtime query 管线独立**，用户需手动使用，未实现自动无感接入
- 无 AI 相关缓存失效策略

### 论文修改建议
- 「AI预测性缓存」改为「提供可扩展的缓存接口（LRU/LFU/FIFO），用户可按需自定义置换策略」
- 「无感知」改为「提供独立的缓存组件，用户可根据场景灵活集成」

---

## 2. 序列化模块

### 论文/任务书中的描述
- 「多格式序列化集成」
- 「自定义类型与特殊格式之间的编码、解码功能」
- 「支持JSON、XML等格式一键转换」
- 「仿照Swift的协议风格……通过继承不同协议获取针对不同格式的转换功能」

### 实际实现
- `examples/coder/coder.hpp` 仅提供 JSON 序列化/反序列化（基于 nlohmann/json）
- 编码器为静态类（两个 static 模板函数），非「协议/继承」风格
- 仅作为示例提供，非核心库功能

### 论文修改建议
- 去掉「XML」「多格式」等具体格式承诺
- 「协议风格」改为「基于 Visitor + SchemaExtractor 的声明式序列化」
- 在 examples 中提供 JSON 序列化参考实现，用户可自行扩展

---

## 3. 表结构迁移

### 论文/任务书中的描述
- 「支持自动建表、智能表结构迁移」
- 「Schema定义发生变化时自动处理表结构变化」

### 实际实现
- `Schema::make_create_table_ddl()` 仅生成 CREATE TABLE 语句
- 无 ALTER TABLE 自动迁移逻辑，无 diff 检测

### 论文修改建议
- 「智能表结构迁移」改为「声明式 Schema 定义，自动生成 DDL，表结构变更需用户确认」
- 仅强调「编译期 DDL 生成」，不提「自动迁移」

---

## 4. 编译期校验范围

### 论文/任务书中的描述
- 「四重编译期校验：SQL语法正确性、表名/字段名的存在性、字段类型匹配性、序列化格式兼容性」
- 「语法校验 + 语义校验」

### 实际实现
- 编译期校验仅覆盖：SQL 词法/语法校验 + DSL 字段定义校验
- 表名存在性检查：**运行时** `init_mapper()` 抛 `unknown column` 异常
- 字段类型匹配、序列化兼容性：未实现编译期检查
- 占位符数量校验：Parser 可解析占位符位置，但严格数量匹配未接入校验管线

### 论文修改建议
- 「四重校验」改为「编译期 SQL 语法校验（词法 + 语法）+ Schema 定义校验」
- 字段类型匹配、列存在性等描述改为运行时校验
- 避免使用「四重」「语义校验」等笼统表述，明确区分编译期和运行时的职责

---

## 5. 多数据库支持

### 论文/任务书中的描述
- 「MySQL、PostgreSQL等多数据库支持」
- 「一套代码适配多数据库」

### 实际实现
- `src/ess/orm/core/mysql/`——仅有空头文件占位
- `src/ess/orm/core/postgres/`——仅有空头文件占位
- 实际仅支持 SQLite3

### 论文修改建议
- 「当前版本以 SQLite3 为主实现，通过 Dialect 接口预留 MySQL/PostgreSQL 扩展能力」
- 将已实现的 Dialect 抽象层作为可扩展性证据，而非声称已支持多数据库

---

## 6. 分布式与高级功能

### 论文/任务书中的描述
- 「为分布式场景预留了扩展能力」
- 「存储函数、存储过程」

### 实际实现
- 无分布式相关代码
- SQL 解析器仅支持 DML（SELECT/INSERT/UPDATE/DELETE）

### 论文修改建议
- 去掉「分布式」描述
- 存储过程/函数在「不足与展望」中提及即可，不作为已实现能力

---

## 7. StatementCache

### 论文中的描述
- 「独立的 StatementCache 模块」
- 「开发者可预先编译常用 SQL 语句并缓存」

### 实际实现
- 缓存在 `sqlite3_connection.cpp` 的 `prepare_cached()` 内部实现（基于 unordered_map）
- 非独立可用模块，与连接实现耦合

### 论文修改建议
- 「独立模块」改为「内置预编译语句缓存机制」
- 重点强调其降低重复解析开销的效果，而非模块独立性

---

## 汇总：论文需调整的部分

| 模块 | 原表述 | 建议修改方向 |
|------|--------|-------------|
| 缓存 | AI预测性、无感知 | 提供可扩展缓存组件，用户按需集成 |
| 序列化 | 多格式、协议风格 | 提供 JSON 序列化示例，声明式 Visitor 方案 |
| 表迁移 | 智能迁移 | 自动生成 DDL，变更需用户确认 |
| 校验 | 四重、语义校验 | 明确划分编译期（语法+DSL）与运行时（列存在性等） |
| 多数据库 | 支持 MySQL/PostgreSQL | 已实现 SQLite3，Dialect 接口预留扩展 |
| 分布式 | 预留分布式能力 | 删除此描述 |
| StatementCache | 独立模块 | 内置预编译缓存机制 |
